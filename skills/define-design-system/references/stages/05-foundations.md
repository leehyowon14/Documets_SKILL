# 05 파운데이션과 토큰

입력: 원칙·대표 화면·지원 환경·브랜드 제약. [플랫폼·참고 시스템](../conditions/platform-and-reference.md)을 적용한다.

## 질문

- 유지해야 할 브랜드 요소와 조정 가능한 요소는 무엇인가?
- 정보 밀도·가독성·강조에서 가장 중요한 과업은 무엇인가?
- 지원할 언어·화면 크기·테마·입력 방식은 무엇인가?
- 토큰의 기준 원본은 어디이고 디자인·코드에 어떻게 반영할 것인가?
- 기존 프레임워크나 토큰 도구의 제약은 무엇인가?

## 방법론 실행

1. 시각 방향이 미정이면 같은 콘텐츠·상태의 대표 화면으로 소수 대안을 비교한다. 이미 합의한 방향이 있으면 적합성만 점검한다.
2. 원칙에 따라 읽기 순서·정보 밀도·주요 행동·오류 인지를 평가하고 선택 근거를 남긴다.
3. 색상 역할, 타이포그래피 위계, 간격·레이아웃, 형태·고도, 아이콘, 모션, 콘텐츠 표현 규칙을 정의한다. 사용하지 않는 영역은 이유와 함께 제외한다.
4. 원시 값→의미 토큰으로 연결한다. 독립적인 제어가 필요한 경우에만 컴포넌트 토큰을 추가한다. 역할이 다른 값을 현재 색이 같다는 이유만으로 합치지 않는다.
5. 타입·참조·테마 대응·허용 사용처를 명시한다. 실제 교환 파일을 만들 때만 DTCG 및 사용 도구 지원을 확인한다.
6. 지원 범위 내 전경/배경 대비, 긴 텍스트·숫자·다국어, 확대, 좁은 화면, 모션 감소를 대표 조합으로 확인한다. 브레이크포인트는 콘텐츠 전환 근거로 정한다.
7. 참조 누락·순환·타입 불일치·테마 매핑 누락을 점검한다. 수치나 구현을 검증할 수 없으면 계획과 미확인으로 남긴다.

## 필수 게이트

- G05-1: 선택한 표현 방향·역할·지원 범위가 원칙과 연결됨.
- G05-2: 토큰의 이름·타입·참조·의미·모드별 대응이 일관되고 끊긴 참조가 없음.
- G05-3: 대표 콘텐츠 조합과 목표 접근성 기준에 대한 설계 점검 근거가 있음. 실제 동작 검증은 07에서 별도 기록.
- G05-4: 디자인·코드의 기준 원본과 동기화 책임이 정의됨.

명목상 팔레트만 있고 실제 배경/텍스트 조합을 확인하지 않았다면 G05-3은 미확인이다.
