# 02 핵심 과업과 우선순위

입력: 01의 범위·문제, 이용 경험 자료. JTBD로 사용 상황과 원하는 결과를 정의하고 여정으로 공통 규칙을 찾는다.

## 질문

- 사용자가 이 과업을 시작한 계기와 최종적으로 얻고 싶은 결과는 무엇인가?
- 최근에는 어떤 대안으로 해결했으며 어디에서 망설이거나 중단했는가?
- 처음 이용하는 사람과 반복 이용자의 흐름은 어떻게 다른가?
- 실패·취소·중단 후 재개 상황에서 무엇이 보존되어야 하는가?
- 첫 버전에서 반드시 완결되어야 할 흐름은 무엇인가?

## 방법론 실행

1. 최근 실제 경험을 시작 계기→행동→판단→결과 순으로 재구성한다. JTBD 문장은 `상황 / 이루려는 진전 / 결과를 판단하는 기준`으로 요약한다.
2. 관찰을 여정 단계, 행동, 질문, 장애물, 회복 경로로 배치한다. 관찰이 없는 부분은 가정으로 표시한다.
3. 단계별 필요한 UI·콘텐츠·행동 규칙을 추출해 후보를 만든다. 정책·서버 기능 요구와 디자인 시스템 책임을 구분한다.
4. 후보를 반복성·실패 영향·재사용성·근거 확실성으로 비교한다. 평가 기준을 기록하고 임의 점수의 합을 객관적 사실로 제시하지 않는다. 접근성 장벽·데이터 손실은 빈도와 별개로 검토한다.
5. 기본적으로 대표 과업 2~3개에서 시작하되 요청 규모에 맞게 조정한다. 순위가 낮아 제외된 항목과 이유도 남긴다.

## 필수 게이트

- G02-2: 정상 흐름과 관련 실패·중단·회복 경로를 검토함.
- G02-3: 초기 컴포넌트·패턴 후보마다 연결된 과업이 있고 우선순위 이유가 있음.
- G02-4: 조사로 확인한 사실과 미검증 여정을 구분함. 필수 정책 미결은 잠정 의존성으로 표시함.
