# 03 디자인 원칙

입력: 반복 관찰·요구, 선택한 과업, 브랜드·제품 제약. Affinity Mapping과 사례 비교로 판단 가능한 원칙을 만든다.

## 질문

- 여러 화면에서 반복되는 사용자 불편은 무엇인가?
- 명확성·밀도·속도·브랜드 표현이 충돌하면 무엇을 우선하는가?
- 어떤 상황에는 원칙의 예외가 필요한가?
- 두 사람이 같은 사례를 판단할 때 자주 의견이 갈리는 지점은 어디인가?

## 방법론 실행

1. 관찰 카드들을 유사한 문제별로 묶고 그룹에 해결할 문제를 설명하는 이름을 붙인다. 소수 사용자에게 큰 장벽인 관찰은 다수 그룹에 묻히지 않게 남긴다.
2. 그룹마다 `원칙 / 이유 / 적용 조건 / 실행 규칙 / 검증 질문 / 예외`를 작성한다. 3~5개를 출발점으로 쓰되 수를 채우기 위해 만들지 않는다.
3. 같은 과업의 대안 두 개를 비교한다. 예: 일시적 토스트와 지속 결과 화면. 각 판단자가 원칙으로 선택 이유를 설명하도록 한다.
4. 판단이 갈리면 조건·우선순위·용어를 보완하고 다른 사례에 다시 적용한다. 혼자 작성했다면 독립적인 합의가 아니라 자체 점검으로 기록한다.

## 필수 게이트

- G03-1: 각 원칙이 실제 문제·요구와 연결되고 적용 가능한 행동 규칙을 포함함.
- G03-2: 충돌 사례에서 선택 근거·우선순위·예외를 설명할 수 있음.
- G03-3: 사례 비교 결과와 참여자/자체 점검 여부가 기록됨.
- G03-4: 제품 담당자의 결정이 필요한 우선순위가 확정되거나 잠정으로 명확히 구분됨. 미결인 핵심 우선순위는 통과 처리하지 않음.
