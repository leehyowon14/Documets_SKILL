# 진행 프로토콜

## 기록 초기화

기존 문서가 없을 때만 [진행 기록 템플릿](../assets/templates/project-state.md)을 `status.md`로 복사한다. [근거·결정 기록](../assets/templates/evidence-and-decisions.md)을 `evidence.md`로 작성한다. 현재 단계의 산출물만 추가하고 빈 파일 전체를 미리 생성하지 않는다. 기존 프로젝트의 동등한 기록 형식은 유지해도 된다.

산출물 경로는 프로젝트 루트와 함께 기록한다. 파일을 쓸 수 없는 환경이면 대화에서 작성 가능한 내용을 제공하고 실제 저장 여부를 명시한다. 저장한 것처럼 보고하지 않는다.

## 단계별 실행 루프

1. `status.md`의 현재 단계·범위·미결 질문과 해당 산출물을 읽는다.
2. 관련 근거를 확인한다. 이전 기록의 가정은 사실로 승격하지 않는다.
3. 단계의 질문 목록 중 자료로 답하지 못한 핵심 1~3개를 묶어 질문한다. 질문에는 필요한 이유와 추천 선택지를 짧게 포함한다. 도구가 없으면 일반 대화로 묻는다.
4. 답변 없이도 가능한 조사·분류·문서 초안을 진행한다. 답이 필요한 브랜드·제품 정책·우선순위는 잠정안으로만 남긴다. 답변을 기다려야 한다면 진행 상태를 저장하고 종료한다.
5. 템플릿을 프로젝트 맥락으로 채우고 결정에 근거 ID를 연결한다. 모르는 내용과 가정의 영향 범위를 명시한다.
6. 단계 파일의 각 게이트를 `충족 / 미충족 / 미확인 / 해당 없음`으로 기록한다. 근거 링크와 적용 범위를 덧붙인다. 해당 없음에는 이유가 필요하다.
7. 상태와 다음 행동을 갱신한다. 요청 범위 내에서 다음 준비된 작업을 계속한다. 형식적인 단계별 승인이나 전체 문서 일괄 질문을 하지 않는다.

## 상태 의미

| 상태 | 조건 |
|---|---|
| not-started | 아직 조사·작성을 시작하지 않음 |
| in-progress | 근거 수집 또는 초안 작성 중 |
| passed | 적용되는 필수 게이트가 모두 근거로 충족됨 |
| blocked | 특정 답변·환경 없이는 해당 단계의 필수 결정을 진행할 수 없음 |
| deferred | 요청 범위 밖이거나 사용자와 합의한 후속 작업. 완료와 다름 |
| stale | 통과 이후 입력·명세가 바뀌어 재검토 필요 |
| not-applicable | 단계가 적용되지 않는 이유가 확인됨. 검증하지 않았다는 뜻으로 사용 금지 |

이 상태는 프로젝트 문서의 상태이며 앱의 goal 상태와 무관하다. 실행 순서는 기본적으로 01~08이지만, 근거가 부족한 상태에서도 의존하지 않는 운영 문서나 검증 계획은 먼저 작성할 수 있다. 미통과 결정을 사용하는 후속 산출물은 `잠정`과 의존 ID를 표시한다.

## 완료 수준

- **초안:** 가정으로 작성했거나 주요 질문이 남음.
- **정의 완료·검증 대기:** 합의가 필요한 결정이 해결되고 명세·검증 계획·운영 규칙이 작성됨. 실제 평가가 없으면 07은 passed가 될 수 없다.
- **파일럿 검증 완료:** 선언한 흐름·명세 버전·환경에서 07 게이트 통과. 전체 서비스 품질이나 모든 사용자에 대한 검증으로 확대 해석하지 않는다.
- **운영 준비 완료:** 요청 범위의 단계 게이트 충족, 담당자·버전·이전·지원 절차 확보. 실제 배포 여부는 별도 사실로 기록한다.

## 근거와 추적

ID 접두사: `OBS` 관찰, `HYP` 가설, `NEED` 요구, `TASK` 과업, `PR` 원칙, `CMP` 컴포넌트, `PAT` 패턴, `TEST` 검증, `DEC` 결정. 기존 프로젝트 ID가 있으면 재사용한다.

각 결정에는 원천 자료·날짜·관찰/사용자 결정/가정/공식 참고의 구분을 남긴다. 참고 시스템의 문서는 우리 서비스의 사용자 조사 결과가 아니다. 샘플 데이터와 가상 사례는 실제 근거 목록과 분리한다.

게이트 실패는 [실패·변경·재개](conditions/revision-and-resume.md)로 처리한다. 검증 근거에 버전이 없거나 이전 버전이면 현재 버전 통과를 주장하지 않는다.
