# 조건: 근거·환경 부족 또는 초안만 요청

| 부족한 것 | 계속할 수 있는 작업 | 완료로 주장하면 안 되는 것 |
|---|---|---|
| 사용자 조사 | 가설, 인터뷰 질문, 과업·패턴 초안 | 사용자 요구가 검증됐다는 주장 |
| 기존 화면 접근 | 제공된 캡처·코드 기반의 제한된 Audit | 전체 화면 조사·실제 동작 확인 |
| 구현 환경 | 명세·상태 모델·검증 계획 | 실제 상호작용·접근성 통과 |
| 담당자·제품 정책 | 선택지, 추천안, 영향 범위 | 담당자 합의·정책 확정 |
| 시간·예산 | 핵심 흐름만 파일럿, 나머지 deferred | 생략한 범위의 품질 보장 |

가정마다 HYP ID, 근거, 틀릴 경우 영향, 확인 방법, 담당자 또는 미정, 다음 확인 계기를 기록한다. AI 역할극·합성 인터뷰는 질문 점검에는 사용할 수 있지만 실제 사용자 검증 결과가 아니다.

필수 결정이 없으면 해당 단계는 blocked 또는 in-progress로 남긴다. 다른 작업은 잠정 의존 관계를 표시하고 진행한다. 사용자가 명시적으로 생략한 활동은 deferred로 기록한다. 침묵을 합의나 승인으로 취급하지 않는다.

전달 문구: "현재 결과는 {{범위}}의 정의 초안/검증 대기 상태입니다. {{항목}}은 {{이유}}로 미수행이며 {{다음 행동}}이 필요합니다."

초안의 실제 기록 수준을 정하기 어려우면 [조사 없는 신규 프로젝트 예시](../examples/provisional-project.md)를 읽는다. 예시의 제품·가설·값을 실제 프로젝트에 복사하지 않는다.
