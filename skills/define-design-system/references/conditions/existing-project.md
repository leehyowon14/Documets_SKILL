# 조건: 기존 프로젝트

적용: 운영 화면, 코드, Figma 라이브러리, 스타일 가이드 중 하나 이상 존재.

- 01에서 서로 다른 역할·과업·상태·화면 크기를 대표하는 표본을 선정한다. 표본과 미조사 범위를 기록하고 전수 조사처럼 보고하지 않는다.
- 이름이 같은 컴포넌트의 동작 차이와 이름이 다른 중복 요소를 모두 찾는다. 빈도가 높은 구현도 결함이 있으면 그대로 표준화하지 않는다.
- 디자인 파일과 실제 코드가 다르면 현재 서비스 동작과 의도된 규칙을 따로 기록한다. 자동으로 어느 쪽을 정답으로 정하지 않는다.
- 04에서 유지/통합/대체/도메인 잔류를 결정하고 현재 API·의존 제품을 기록한다.
- 05~06은 기존 토큰과 API를 새 규칙에 매핑한다. 호환 별칭·폐기 시점·단계적 이전이 필요한지 판단한다.
- 07 파일럿에는 기존 사용처 회귀 확인을 포함한다. 08에 이전 방법과 되돌릴 범위를 기록한다. 정의 요청만으로 기존 코드를 일괄 교체하지 않는다.

추가 질문: 반드시 호환되어야 하는 제품과 버전은 무엇인가? 기존 기준 원본은 어디인가? 이번 작업은 현황 정리, 점진적 통합, 전면 교체 중 어디까지인가?

산출물 보정: 기존 요소→신규 요소 매핑과 예외 목록을 04, 08에 포함한다.
