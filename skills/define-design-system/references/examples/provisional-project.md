# 작성 예시: 조사 없는 신규 프로젝트

이 파일은 가상 입력을 적용한 작성 예시다. 실제 조사·검증 결과가 아니다. 질문을 줄이고 확인된 사실과 가설을 구분하는 방법을 보여준다.

## 가상 요청

> 신규 예약 서비스의 디자인 시스템 초안을 만들어줘. 모바일 웹이고 React를 쓸 예정이야. 인터뷰 자료나 브랜드는 아직 없고, 지금은 문서만 필요해.

## 시작 시 판단

- 확인된 결정: 신규, 모바일 웹, React 예정, 문서 범위.
- 읽을 파일: 진행 프로토콜, 신규 프로젝트, 근거 부족, 현재 단계 01과 템플릿.
- 초기 질문: "첫 출시에서 예약하는 대상과 주 사용자는 누구인가요?", "이번 초안에 포함할 흐름은 예약 생성까지인가요, 변경·취소까지인가요?"
- 이미 제공한 플랫폼·구현 범위는 재질문하지 않는다. 브랜드 선호는 05에서 필요할 때 묻는다.
- 사용자 답변 전에는 입력 자료와 범위 초안을 기록하고, 핵심 대상·과업은 미확정으로 남긴다.

## 가상 후속 답변

> 소규모 회의실을 빌리는 고객용이야. 첫 범위는 검색, 예약 생성, 결과 확인까지. 내가 제품과 디자인 결정을 맡을게.

이 답변은 범위를 정하는 근거이지 실제 사용자 행동의 증거는 아니다.

## 범위·근거 기록 발췌

| ID | 종류 | 내용 | 근거·한계 |
|---|---|---|---|
| DEC-01 | 사용자 결정 | 회의실 검색→예약→결과 확인을 초기 범위로 설정 | 가상 후속 답변, 취소·변경 제외 |
| HYP-01 | 미검증 가설 | 고객은 예약 요청 후 확정 여부를 명확히 알아야 함 | 실제 이용 경험 조사 필요 |

HYP-01 확인 계획: 최근 회의실 예약 경험을 인터뷰하고, 요청·확정 구분에서 망설임이 있는지 확인. 담당은 제품 담당자, 시점은 첫 파일럿 전. 틀리면 결과 패턴의 정보 위계를 재검토한다.

## 추적 발췌

| 근거 | 요구 | 과업 | 원칙 후보 | 패턴 후보 | 검증 계획 |
|---|---|---|---|---|---|
| HYP-01 | NEED-01: 처리 상태 이해 | TASK-01: 예약 결과 확인 | PR-01: 상태와 다음 행동 안내 | PAT-01: 제출 결과 처리 | TEST-01: 느린 응답에서 상태 이해 관찰 |

PR-01·PAT-01은 잠정이다. 실제 사용자 관찰이 없으며 TEST-01 결과는 미수행이다.

## 상태 기록 예시

| 항목 | 상태·내용 |
|---|---|
| 현재 단계 | 02 in-progress |
| 01 | 범위·담당자·제외 범위 및 기준선 수집 계획을 기록한 뒤 게이트별 평가 |
| 07 | deferred — 이번 요청은 문서 초안이며 실제 평가는 범위 밖 |
| 완료 수준 | 초안 |
| 다음 행동 | 사용자 여정의 가설과 정상·실패 경로를 작성 |
| 실제 구현·배포 | 미수행 |

초안 작성 중에는 모든 단계를 passed로 만들지 않는다. 나중에 정책·명세가 확정되어도 실제 평가를 수행하지 않았다면 완료 수준은 최대 `정의 완료·검증 대기`다.
